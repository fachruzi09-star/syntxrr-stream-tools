## V53 Direct Capture Teardown Finding
- RootEncoder's `StreamBase.stopStream()` stops the current `VideoSource` before encoders are released, and `release()` stops sources again before releasing the source and GL resources. The custom Direct source's `stop()` therefore must not return while an already-running callback can still forward a frame to the GL interface.
- V53 moves `HandlerThread.quitSafely()` and a bounded 200 ms join after the source lock is released. This makes the stop operation a retirement barrier for normal callbacks; if the callback thread exceeds the bound, the source logs a warning rather than waiting indefinitely. The standalone harness passed 9 assertions; a stubbed Java syntax/type check passed, but no full Android build was run.
- Compatibility Object Layer callbacks are main-Looper serialized; its one-`VirtualDisplay` guard and generation checks were audited but not changed. Device validation is still required for both engines.


## V54 Direct Projection Readiness Finding
- The Direct `SurfaceTexture` listener previously emitted first-frame readiness through a generation-blind callback. If a callback entered on the old projection, overlapped `suspendProjection()`, and returned after `firstFrameDelivered` had reset, it could mark the new projection ready before a new frame arrived.
- V54 snapshots the source generation before forwarding; after forwarding it requires the same generation and an attached projection/VirtualDisplay before changing `firstFrameDelivered`. The callback carries its generation to the service, which checks it again on the main Looper before publishing readiness.
- Six pure-Java policy tests passed. A deterministic stubbed integration harness also passed old-callback-after-suspend/reattach, current-generation acceptance once, detached callback rejection, and re-arming on the next generation. No Android Gradle build, APK, or physical-device test was run.
